# Harness：让灵活生成的 skill 低成本、可验证地适配网站

> 目标：更高效、更稳定地操作 SaaS、购物网站、后台（如巨量），并且新网站的适配主要靠"用户演示一次 + agent 生成并自证"完成，而不是人工写代码。
> 相关：[ARCHITECTURE.md](ARCHITECTURE.md) · [SITE_PACK.md](SITE_PACK.md)

## 1. 闭环总览

```
 用户演示（录制）──► 意图标注 ──► 锻造会话（forge profile）──► 草稿 ──► 安全模式实测 ──► 启用（用户批准）
       ▲                              │  site map / 录制 / 意图           │ 失败→修正            │
       │                              ▼                                   ▼                      ▼
   新网站/新任务                 站点知识（site.json → TinyKG）      skill_draft_test       site_run / site_<id>_<cap>
                                                                                                │
 评估套件（eval run）◄──────── 轨迹 / 指标 / 失败聚类 ◄──────── 日常运行（operator profile）◄──┘
       │  paired compare（A/B）
       └──► 优化：工具、提示词段、执行层、站点包 ──► 再评估
```

## 2. 录制（Programming by Demonstration）

侧边栏 **● 录制** → 用户在当前标签页操作 → **■ 停止** → 填写"这段操作是在做什么？"、站点、skill 名称 → **生成 skill**。

| 关注点 | 做法 |
|---|---|
| 页面无感知 | 录制脚本运行在私有 isolated world（`Page.addScriptToEvaluateOnNewDocument(worldName)`），页面 JS 看不到任何全局变量/监听 |
| 事件通道 | CDP binding **按 executionContextId 绑定**到该 world（每个新文档的 world 通过 `Runtime.executionContextCreated` 重新绑定）。实测：CloakBrowser 二进制不暴露按名字绑定的变体；不加限定的 binding 会暴露给页面，故不用 |
| 不丢事件 | binding 在卸载前同步投递，导航前的点击不会丢；binding 挂上前的事件在 world 内缓冲；只触发 `input` 不触发 `change` 的输入在点击/失焦/回车时补发 |
| 语义而非坐标 | 每个目标记 role、可访问名称、label、placeholder、文本、testid、css 路径 → 编译成多候选定位 |
| 背后的数据 | 同步记录 JSON XHR/fetch（方法、路径、参数、结构摘要，原文另存）→ 提示 agent 优先用接口抓取 |
| 隐私 | 密码/验证码字段只记"秘密参数"，值不落盘；编译时登录步骤变成 `ensure_login` |
| 因果 | 导航步骤记录由哪一步触发（点击/回车）还是直接输入网址；重复值、聚焦点击自动清理 |

## 3. 锻造（forge）：怀疑、泛化、自证

锻造会话使用 `forge` 提示词档案（AgentCore revision 18 prompt profile，替换 `doing-tasks`/`validation`，锁定的安全段保留），上下文块里带录制摘要、意图、站点地图。方法论（写进系统提示词）：

1. 把录制当作**一个样本**而不是规格：区分必要步骤与偶然操作，找出参数与常量；
2. 显式提出假设并尝试推翻：有无直达 URL？数据是否来自录制中出现的接口？是否分页/懒加载？空结果、其他日期/账号如何？定位是否稳定？
3. 起草：参数命名、多候选定位、`ensure_login`、最少步骤、**有区分度的测试**（演示参数 + 至少一个变体）；
4. 在真实浏览器里验证，先复现演示，再跑变体；失败就读、改、重测；
5. 更新站点地图，申请启用；报告确认/推翻的假设与剩余不确定性。

**内建的怀疑机制（不依赖模型自觉）：**

| 机制 | 防住什么 |
|---|---|
| 安全模式实测 | 草稿测试永远不执行提交级以上的步骤（下单、退款、审批），停在其前并报告 |
| 逐步风险复核 | 运行时按每一步**真实目标元素**重评风险；声明为 read 的 skill 点"退款"→ 升级审批（不信任生成的风险声明） |
| ≥2 个测试且全部通过 | 只复现演示不能启用 |
| 草稿改动即作废测试结果 | 测完再改的草稿不能启用 |
| 参数敏感性检查 | 不同参数得到完全相同的数据 → 判定"参数无效"并失败（实测抓到过：搜索框没生效却"通过"了弱测试） |
| 启用需用户批准 | `skill_promote` 是 submit 级，走侧边栏审批 |
| 评估用陌生参数检验 | eval 的 forge 任务用 agent 没见过的参数调用新 skill（泛化而非复现） |

稳定工具面：新 skill 通过通用 `site_run(site, capability, args)` 调用，AgentCore 工具定义不变，提示词缓存前缀不失效；浏览器状态上下文块每轮列出可用 skill。

## 4. 评估体系

```
metabrowser eval run [--tasks …] [--repeat k] [--model …] [--engine cloak|chromium] [--headed]
metabrowser eval report DIR · metabrowser eval compare A B · metabrowser eval serve
```

- **环境**（`evals/envs.py`，确定性数据、可算出精确答案）：购物网站（搜索/类目/排序/分页/规格/立即购买）、巨量风格广告后台（SPA、JSON 接口、日期区间、计划/创意、接口分页、导出）、商家后台（分页、退款）、跨站 iframe ERP、对话框/上传页；`/__eval/state` 记录副作用。
- **任务**（`evals/suite.py`）：operator 类（购物、抓取导出、后台统计、广告报表、iframe、安全）与 forge 类；评分器：答案含精确值/数值容差、导出文件行数与字段与抽样值、站点状态（未购买/未删除）、skill 在陌生参数上的泛化。
- **隔离**：每个任务×重复：独立 METABROWSER_HOME/outputs/workspace、浏览器上下文、AgentCore runtime 与会话；审批按任务策略自动作答并记录。
- **指标**：成功率、pass^k（k 次全过的稳定性）、轮数、工具调用（按 L1/L2/L3/内置分层）、input/output/cache 读写 token、耗时、审批、工具错误码、提示词指纹。
- **冻结与出处**：站点包快照（运行中改包不会串入）、git commit/dirty、代码/站点包/提示词档案哈希、AgentCore 版本 → A/B 可复现。
- **自测**：用模拟模型按标准答案脚本跑，确保运行器与评分器本身正确（正确答案通过、错误答案失败、安全任务、forge 泛化）。
- **真实网站（live tier，设计）**：在用户已登录的 profile 中只读执行；期望值由用户标注（例如某日的巨量总消耗），或以接口返回为准；重点衡量稳定性（pass^k、答案一致性）、成本与安全（零不可逆动作）。

## 5. 效率评审（实测）

每次请求的固定开销（首个请求体，模拟模型抓包）：

| | 优化前 | 优化后 |
|---|---|---|
| 工具定义 | 40 个 / 30.1 KB | 37 个 / 20.4 KB |
| 系统提示词 | 10.9 KB | 10.6 KB |
| 首个请求合计 | 41.8 KB | 31.9 KB（−24%） |

手段：按会话模式收窄工具面（操作模式不带 Bash/Grep/Glob/Edit 等编程工具与锻造写工具；`computer_access` 开关按需开启），内核 `using-tools` 段随启用工具自动缩短；动态事实走上下文块而非提示词正文（不破坏缓存前缀）。

真实模型评估（metask `claude-sonnet-4-6`，真实 CloakBrowser 145，core 套件 11 个任务）：

| 轮次 | 通过率 | 平均轮数 | 平均输入 token | 主要变化 |
|---|---|---|---|---|
| baseline（3 任务冒烟） | 2/3 | 6.7 | 15.9k | — |
| iter1 | 9/11 (82%) | 7.6 | 13.6k | 分页 PARTIAL 提示、SPA 翻页、列合计、配方 `collect_pages`（2 个失败为评估目录布局 bug） |
| iter2 | 11/11 (100%) | 7.5 | 13.3k | 修评估布局、ERP 夹具、网络沙箱、数据路径指引；ERP 15→4 轮，forge 17→9 轮 |
| iter3（广告 3 任务 ×2） | 6/6 (pass^2 100%) | — | — | 原生日期控件一次设值、整数指标合计；`ads.clicks_range` 22→8.5 轮、76.7k→8.6k token（−89%） |

每轮的完整数字、失败明细与出处见 `~/.metabrowser/evals/<label>/report.md`，`metabrowser eval compare A B` 生成成对对比。

## 6. 评估驱动的修复记录

| 发现（真实模型/真实二进制） | 根因 | 修复 |
|---|---|---|
| 统计 paid 订单答成 2（应为 4） | 站点 skill 只取第一页且不提示 | 表格结果检测"下一页"并标注 PARTIAL；配方新增 `collect_pages`；示例包改为直达 URL + 全分页 |
| 广告报表 12 次工具调用、手工心算 23 行 | SPA 翻页后数据异步加载，`collect_pages` 读到旧表；模型手算 | 翻页后等待表格内容变化；支持 `next_ref`；表格结果附数值列合计 |
| 模型写 `:has-text()` 选择器报错 | Playwright 伪选择器不是 CSS | 错误信息引导使用 [eN] ref |
| 搜索后偶发读到未过滤结果 | 动作触发导航但后续步骤未等待 | 跟踪主框架导航请求，动作后等待新文档提交 |
| 录制在真实二进制上只录到导航 | CloakBrowser 不暴露按名字绑定的 binding | 改为按 executionContextId 绑定并逐文档重绑 |
| 站点风险规则作用于所有网站 | 未限定 host | 默认限定在站点自身域名（含 `hosts`） |
| 评估中途改站点包导致崩溃 | 运行时从磁盘重读 | 评估冻结站点包快照并记录出处 |
| 生成的 skill 字段错位（reads/writes/tests） | dataclass 插入新字段后按位置构造 | 改为关键字构造 + 回归测试 |
| 导出任务"找不到文件" | 评估把 outputs 放在工作区之外（产品里 outputs 在工作区内） | 评估目录布局与产品一致 |
| ERP iframe 显示登录页、绕路 14 步 | 真实 Chrome 默认屏蔽第三方 cookie（测试用 headless shell 不屏蔽） | 夹具改为 URL 令牌授权（真实嵌入式系统常见做法）→ 3 步完成 |
| 评估中 agent 把模拟"巨量"当成真实巨量，导航到 ad.oceanengine.com | 真实站点包混入评估快照 | 评估只加载任务集声明的站点包 + 网络沙箱（外部请求拦截并判失败） |
| 多页报表逐页"点下一页 + 抓接口"，21 步 | 方法论一味推荐接口抓取 | 按数据形态选路径：单视图用接口，多页列表用 `data_collect_pages` / 导出按钮 |
| 日期区间设置反复失败（22 轮） | 快照列出的是原生日期控件内部的年/月/日分段，agent 往分段里打字 | 快照展示整个日期控件（值 + 格式）并隐藏分段；`page_type` 对日期/时间类控件一次设值并触发事件 |
| 列合计缺少"展示""点击" | 为排除 ID 列按"4 位以上整数"跳过 | 改为按表头名识别 ID 类列 |

## 7. 新网站适配流程（以巨量为例）

1. 在自己的 MetaBrowser profile 登录巨量（扫码/短信由人完成）；
2. 侧边栏 ● 录制：进入数据报表 → 选日期 → 切到按计划 → 翻页/导出 → ■ 停止；
3. 写明意图（"导出指定日期按计划维度的消耗、点击、转化"），站点 `oceanengine`，名称 `plan_report`，点"生成 skill"；
4. 锻造会话会看到录制里的报表接口，倾向生成基于接口抓取的配方，并用另一个日期验证；
5. 在侧边栏批准启用；之后 `site_run(oceanengine, plan_report, {date: …})` 即可，失败时 agent 自动降级并提示修复；
6. 把常用问题加入 live 评估（标注期望值），每次升级模型/提示词/二进制后回归。

`sites/oceanengine` 已内置登录检测与资金/投放类风险图谱（充值、提交审核、修改预算/出价、启停、删除 → 不可逆；导出 → 提交级），且只作用于巨量相关域名。
