# HRTF 计算路径与当前验收

当前候选 v20l2：`f46dc3e5ff57df7498af5f12beb3aaa987fc6c375876b6138b12dd3a480fdd00`。
状态：诊断后端的有限验收通过；完整 HRTF、跨 CPU、生产 profile 激活与全量指纹隐私未完成。
此应用没有 SDK，未替换日常浏览器。

源码检查确认：HRTF 由加载线程按采样率创建数据库，从固定资源读取脉冲响应，
经过重采样、群延迟提取、相位调整和频域插值形成卷积核。数据库缓存当前按采样率组织；
诊断后端由进程启动模板固定，本轮没有改变缓存键或证明运行中切换模板安全。

原生修改仅针对显式可移植 FFT 后端：

- 有限复数幅值使用缩放后的平方根计算，避免中间平方溢出/下溢；禁止乘加收缩和重排。
  极值分类与原生路径由实际生产函数的 2026 个数值用例及 UBSan 检查。
- 相位使用 fdlibm atan2，有限极坐标重建使用 fdlibm sin/cos。
  polar 的非有限值或负号特殊域仍保留标准库语义，不能宣称所有异常域已统一。
- 原生模式仍调用原来的 complex<double> 标准库表达式。

当前实际浏览器测试覆盖三档采样率、前/左/右三个位置、单脉冲与延迟双脉冲、重复两次。
每模式 36 图、72 个完整声道输出、294912 个 float32 值；两模式合计 72 图、589824 值。
检查实际非零且有时间延展的响应、方向性双耳能量、前方对称、两条读取路径、重复一致，
以及全部采样的线性叠加关系。最大叠加误差为零。这些是功能条件，尚不是独立 HRIR
数据库数值 oracle、完整姿态网格或全部动态变化验收。

第一轮数学修改后的输出在此矩阵中与旧版相同，故没有拿“输出相同”作为分支触发证明。
之后在三个真实 C++ 方法加入原生追踪点，当前观测为每模式：

| 阶段 | 实际调用数 |
| --- | ---: |
| 群延迟提取 | 1440 |
| 频域插值 | 10080 |
| 相位调整 | 1440 |

诊断模式全部记录 portable=true，原生模式全部为 false。记录来自原生方法调用，
不是网页 getter 或硬编码的期望字段。诊断输出在本矩阵中仍不变；原生 72 个完整声道
摘要也与 K2 一致。每模式 14 类错误被拒绝，包括完整 payload/两个摘要一同更新的
零输出/伪 equalpower、违反线性关系的重复对齐数据、错误后端/缺失追踪阶段。

旧 K2 与首轮 L 的 231 个 pak/wav 资源条目相同；当前 L2 也已核验并绑定资源、
