# AgentCore 工具体系与 Browser Harness v0.4

日期：2026-10-15。下文为完整目标工具体系；当前落地接口以本节为准，不能把目标目录理解为全部已交付。

实际注册以 `src/browser_tool_catalog.json` 为单一来源，构建时核对生成的 Zig 与 C++ 目录：`browser_tabs`、`browser_navigate`、`browser_observe`、`browser_act`、`browser_execute`、`browser_tab_open`、`browser_tab_activate`、`browser_tab_close`、`browser_status`、`browser_inspect`、`browser_extract`、`browser_wait`。内嵌 MetaCodes 与外部 MCP 使用同一原生 Browser Broker、参数验证与任务占用，不引入第二套浏览器驱动。以下目标工具表不代表媒体、文件传输、WebMCP 或任意坐标输入已经交付。

同一 AgentCore 接入 SDK coding 工具和标准 MCP（stdio / Streamable HTTP），原生 UI 处理权限。外部任务走可选 A2A 1.0 本地网关，仍使用同一可见 Session。Jev 是可替换策略的预留方向，当前没有接入其推理 API。详细范围见 [AGENT_PROTOCOL.md](AGENT_PROTOCOL.md)。

## 原生 harness 运行契约

- 观察使用各 live frame 的真实 AX tree；最多 32 个 frame、扫描 8192 节点。fenced frame 不进入观察；不可用 frame 与截断显式返回。支持后台标签语义读取，动作和视觉捕获要求当前激活标签。
- 默认观察最多 256 节点、16 KiB；可配置到 2048 节点、64 KiB。交互过滤、紧凑模式、文字查询和 frame 范围减少上下文。保留有界身份字段，不复制完整 AX 属性到长期快照。
- 数字 ref 对同一 frame 文档中的存活节点稳定、不回收；动作许可另由 30 秒内的 `observation_id`、标签和文档验证。动作消费该标签已有观察。替换节点/子文档、关闭标签、取消均不能沿用旧目标。
- `delta` 必须指定兼容 `baseline_id`，返回变化节点、删除引用和 `ordered_refs`；基准缺失、范围不同或差分超过预算时返回完整观察。仅保留最近 8 份快照。
- `browser_inspect` 和 `browser_extract` 保留观察/文档/URL 来源与覆盖范围。无 target 时只读取本次观察集合；表格和正文不能据此宣称分页完整。
- `browser_wait` 在本地以 100 ms 有界检查 ready、精确 URL、文字、唯一 name/role 条件，最长 10 秒。导航通过实际完成事件收尾；ready 仅表示导航/加载结束。等待不消耗模型轮询调用。
- click/check/select 是 AX 语义激活；执行前自动滚入视口、采样几何稳定性，再做异步 renderer AX hit test，遮挡、过期、禁用或保护字段拒绝。`fill` 是可编辑文本控件的 AX setValue。它们不承诺完整鼠标/逐键事件语义；Canvas 连续输入尚不支持。
- `browser_navigate` 和 `browser_execute` 必须携带从 status/observe 获得的 `tab_id` 与 `document_id`。外部确认还绑定确认前的激活标签与目标文档，确认期间上下文变化后必须重新观察。
- `browser_execute` 最多 12 步、20 秒；唯一 name/role 定位、逐步观察与条件核验。fill 的 expect_text 必须等于 text，并核验原始目标引用及子文档；其他步骤要求新出现的条件文字，拒绝把已有文字当作执行证据。部分执行失败返回 effects_dispatched、preparatory_scrolls_dispatched、last_action / needs_reconciliation，区分激活与准备滚动；任一已发生都要求重新观察，不盲目重放。
- visual 可传 `annotate:true` 与新鲜语义 `observation_id`，最多标注 64 个可见非保护引用。返回真实图像尺寸、DIP 视口和图像坐标标注；捕获后重验文档、控件与 bounds。AX 与合成器没有原子快照保证，标注不能替代命中验证。
- 窗口内仅一个任务持有 harness：SDK 会话、外部直接工具和账户操作共用占用规则。取消撤销观察与待执行动作；读写工具不能扩展用户授权。结果区分 dispatched / completed / stale / not_ready / ambiguous / timeout / cancelled，局部条件成立不代表业务任务成功。

设计参考 [agent-browser dac13bb8](https://github.com/vercel-labs/agent-browser/tree/dac13bb87468fe9d74a040d862720f6cc17a9565)。我们吸收交互闭环与成本控制方式，执行仍由 Chromium C++ 和 Zig 宿主实现；未打包其 Rust CLI、Python wrapper 或新浏览器实例。WebMCP、媒体和持续输入须独立验证后开放。

## 1. 三类任务，共用一个受约束的执行基础

| 场景 | 工作方式 | 关键验收 |
|---|---|---|
| 查公开联系方式 → 邮箱草稿 → 发送 | 跨站数据传递与事务 | 来源可追溯、发件身份正确、批准的内容与实际发送一致、不重复发送 |
| 财务异常 → ERP → CRM → BI | 可分支、可回溯的证据调查 | 实体关联依据、冲突事实、统计分母和范围、未解决问题保留 |
| 攻略视频 → 游戏执行 → 纠错 | 多模态学习与动态反馈 | 时间片证据、当前游戏状态匹配、有限动作、反馈检查、输入可靠释放 |

核心闭环：观察 → 决策 → 检查授权/状态 → 执行 → 验证 → 更新任务记录。
模型可提出下一步，不能凭自己的陈述确认权限、观察有效性或任务成功。

## 2. 职责与成本边界

| 层 | 应负责 | 不应承担 |
|---|---|---|
| 浏览器 C++/Mojo 适配 | 标签/身份/焦点、页面观察、原生输入、命中检查、权限与执行证据 | 模型规划、任意模型脚本、伪造成功结论 |
| AgentCore / Zig Host | AgentLoop、任务计划、工作数据、模型路由、预算、工具状态与取消 | 冒充 Chromium 的实际执行结果 |
| 确定性计算与本地控制器 | 精确计算、表格操作、变化检测、有界动作时序、已验证流程 | 自行扩大任务、授权或提交范围 |
| 模型 | 理解目标、关联证据、处理视觉歧义、选动作、修订假设 | 持有浏览器内部指针、决定自己的权限等级 |

本地工作目录的文件读写、编辑、搜索、终端、进程和测试是一级能力，复用 MetaCodes coding 工具体系。
脚本可以使用受支持的语言，通过宿主 facade 操作浏览器。工作目录权限不自动包含 profile、Cookie、密码、其他目录或任意网络权限；这些限制必须由执行环境落实，不能只靠模型遵守。
以后的网站 API 连接器应单独声明身份、权限、来源及审计语义，不作为偷偷替换 UI 行为的通道。

## 3. 稳定工具分组，站点能力按需加载

入口较少不代表把所有操作塞进自由文本。每个 op 有有界、可验证的参数 schema。
只向模型声明当前任务已获授权且确实可用的工具与 op；隐藏工具不替代执行侧鉴权。
工具描述保持稳定且可缓存；动态页面状态通过结果提供，不能不断重写工具 schema。

| 工具 | 所属层 | 主要 op / 内容 | 可用范围 |
|---|---|---|---|
| `browser.tabs` | 浏览器 | list / open / activate / close；标签用途、身份句柄与占用情况 | 基础 |
| `browser.navigate` | 浏览器 | goto / back / forward / reload | 基础；导航与 URL 携带的数据也要检查 |
| `browser.observe` | 浏览器 | semantic / visual / hybrid / delta；范围、关注项与输出预算 | 基础 |
| `browser.inspect` | 浏览器 | 查询目标、局部图、元素/区域详情、受限可见文本 | 基础 |
| `browser.act` | 浏览器 | click / fill / select / scroll / key / drag | 基础；提交同样经过浏览器原生检查 |
| `browser.wait` | 浏览器 | 等待观察到的条件、导航、变化、下载等事件 | 基础 |
| `browser.extract` | 浏览器 | 正文、表格、链接、指定字段、分页游标、来源及覆盖范围 | 数据任务 |
| `browser.transfer` | 浏览器 | 选定文件上传、下载结果、限定文本剪贴板交互 | 按需授权；禁止任意本地路径读取 |
| `task.data` | AgentCore | put / get / query / link / compare / mark；事实、假设、问题和来源 | 跨站任务 |
| `analysis.compute` | AgentCore 本地服务 | filter / project / join / group / aggregate / decimal arithmetic | 调查任务 |
| `media.read` | 浏览器媒体适配 | metadata / transcript / frames / seek / playback | 视频任务 |
| `input.perform` | 浏览器有界执行器 | 带时长的输入片段、组合键、轨迹；停止与释放 | 动态交互任务 |
| MCP 服务工具 | 标准 MCP Client | 使用服务提供的原始名称及 schema，宿主隔离命名空间 | 按任务、权限和服务可用性加载 |
| 工作区文件工具 | MetaCodes Coding | read / write / edit / glob / search | 能力分组；具体名字复用 SDK 实际接口 |
| 终端与进程工具 | MetaCodes Coding | 命令、后台进程、输出读取、取消、测试 | 受工作目录、网络、时长及进程权限约束 |

审批是浏览器/AgentCore 的宿主协议，不给模型一个“批准自己”的工具。
取消、释放输入、回收资源属于宿主控制面；不能依赖模型主动调用某个工具才能生效。
报告可由模型引用工作区证据生成，无需为每种业务再建立一个巨大工具目录。

Skill 保持本地，沿用 MetaCodes 加载机制，不在本次扩展其协议。外部服务通过标准 MCP 接入，KnowForge 与其他 MCP 服务采用同一连接机制，不新增 skills.find/run 包装层。MCP 提供的地图、说明或代码作为上下文和文件使用；analysis.compute 是确定性快路径，复杂计算仍可直接写代码完成。

## 4. 统一请求和结果协议

宿主注入 session/run/request、能力令牌、截止时间和任务预算。模型不能选择别人的
run、伪造 token 或增加预算。模型只提供业务参数、观察引用与预期条件。

```json
{
  "tool": "browser.act",
  "arguments": {
    "observation_id": "obs_42",
    "target": {"element_ref": "e17"},
    "op": "click",
    "expect": {"kind": "element_visible", "name": "保存成功"},
    "result": {"mode": "delta"}
  }
}
```

结果的公共部分包含：

- `request_id / observation_id / tab / frame / document_epoch / view_epoch`。
- `status`：completed、rejected、stale、cancelled、timeout、unknown、unsupported。
- `execution`：未开始、输入已派发、等待结果、已确认；明确具体确认了什么。
- `evidence`：变化摘要、提取记录、图像附件引用、可验证的状态条件。
- `coverage`、`truncated`、剩余分页游标；不能静默截断后假装完整。
- `usage`：本地耗时、传输字节、返回体积等；模型费用由 Core 单独计量。

`completed` 是指定操作或条件完成，不意味着用户整体目标已达成。
点击事件被派发与“订单已提交”“邮件已送达”不能共用同一个成功含义。
页面成功提示只是一个证据；不能据此声称收件人已收信或已读。

副作用操作分配 request id 和去重记录。超时/连接中断若无法确认结果，返回 unknown，
先检查草稿、已发送、交易记录等，不盲目重发。去重记录也不能保证外部网站恰好执行一次。

## 5. 多模态观察与新鲜度

一次观察由同一观察编号关联：图像/文字/元素、URL、标签身份、焦点、滚动、缩放、
像素尺寸、坐标变换、frame、文档/视图世代、采集起止时间及一致性标记。
截图和树并非天然原子同步：采集期间发生导航或布局变化时，标记不一致并重采或拒绝动作。

动作优先使用 observation 内的 element_ref。Canvas 等场景允许坐标目标，但必须绑定
原截图的坐标系；执行前检查焦点、视口、遮挡、命中目标和视图变化。不能把视觉置信度
当作坐标仍然有效的证明。元素引用也要重新验证，不能把 AX node id 永久保存为操作目标。

新鲜度策略：

- 导航、账户切换、frame 替换与用户接管立即使相关授权/引用失效。
- 布局、焦点、遮挡变化可能让坐标失效，即使文档没有导航。
- delta 必须注明基准观察；基准缺失、变化追踪有缺口或模型重置时返回完整观察。
- 静态区域可复用图像资产，但不能靠图片哈希相同来证明全部页面状态相同。
- 用户自己的浏览标签不自动归 Agent 占有；共享页有显式租用与接管事件。

图像按任务内容选择：表格/文本优先结构化读取，视觉任务保留必要图像。
局部裁剪保留其原图位置与尺寸，必要时回退全局视图，避免裁剪掉上下文和遮挡信息。

## 6. 信息量分级与上下文控制

观察不是每一步都截全屏。建议分级：

1. L0：轻量状态与事件——页面/焦点是否变化、是否满足等待条件。
2. L1：有界语义摘要、目标附近元素和变化。
3. L2：目标区域图像及相关结构。
4. L3：完整视口图像与结构。
5. L4：按时间采样的视频片段，仅在运动理解确有需要时启用。

视觉任务可直接从 L2/L3/L4 开始，不能为了便宜强制先做无用文本推理。
变化检测只是调度信号，可能漏掉细节；设置周期复核和异常升级条件。

初始原型可试用“语义结果约 16 KiB、全局图长边约 1280 像素、局部裁剪保留原始清晰度”
作为默认输出预算，并按任务动态调整。这些是待测起点，不是识别准确率或费用承诺；
文本表格过密时不要只缩图，应提取数据或使用局部图。

大表格、长正文和视频存为带权限的 artifact，默认只回摘要、schema、覆盖范围和引用。
Core 根据需要取片段，避免把全量资料反复写进 Conversation。引用需要经过 Core 解析
与 provider adapter 交付；仅给模型一个本地文件路径并不构成视觉输入。

资产缓存以任务/权限/账户隔离。站点中的指令文本属于不可信数据，不变成宿主授权。
敏感内容脱敏，保留脱敏位置以维持坐标含义；密码等机密使用受限句柄，避免进入模型上下文。
资料撤销、任务结束、保留期限到期时，关联资产与缓存都需要处理，而非永远保存。

## 7. 跨站工作数据：事实不等于推断

`task.data` 管理任务级记录，首版采用 schema 约束的记录与关系即可，不先建设通用知识库。

```json
{
  "id": "contact_7",
  "kind": "fact",
  "entity": "customer_12",
  "field": "email",
  "value": "someone@example.com",
  "source": {"observation_id": "obs_42", "record_ref": "r9"},
  "observed_at": "<timestamp>",
  "verification": "observed_not_independently_verified",
  "sensitivity": "contact",
  "allowed_use": {"task_scope_ref": "grant_3"}
}
```

保存来源原文/局部证据、实际账户及查询范围。脱敏账户标识足够时，不向模型提供完整账户信息。
事实、假设、候选实体关联、冲突与待查事项分开。模型的置信评分不自动变成统计概率或事实。
`link` 只声明带依据的关系；近似名称、相似地址不自动合并成同一客户。

跨站传递直接通过有权限的数据引用填入目标字段，不强制使用全局剪贴板。
读取授权与对外传递授权分别检查。URL 查询参数、表单提交、上传等都可能形成对外传递。
跨站使用在任务授权范围内不逐步打断；超出目标、接收方或用途时再请求用户决定。

## 8. 调查与 BI 的确定性计算

`analysis.compute` 接受数据集引用和受限操作树，不接受 Python/JS/SQL 任意执行字符串。
支持有界 filter、显式键 join、group、aggregate 和 decimal 计算；不得自动发起外部访问。

- 金额保留币种和 decimal 精度；单位、日期、时区显式。
- join 报告一对多、重复、缺失和未匹配记录，不静默丢行。
- 统计“发生率”必须有问题定义、时间范围、过滤条件、分子/分母、去重口径和覆盖范围。
- 分页未取完、导出被截断、只有样本时，不能宣称得到总体发生概率。
- 可验证的 BI 聚合结果可复用，保留指标定义和筛选条件；不必为了计算再读全量明细。
- 本地计算也有行数、内存、执行时间和输出上限，避免把省 token 变成内存耗尽。

## 9. 视频学习与动态输入

`media.read` 返回字幕的来源/可用性、时间片、关键帧及媒体版本；自动字幕需要与画面交叉核对。
先用元信息、字幕和章节定位，再按需求选择关键画面和短片段。关键帧可能漏掉动作过程，
不理解时扩大时间窗口，不把离散截图当成完整运动证据。

学习产物是“前提/目标/状态条件/动作候选/失败分支/视频时间证据”，不是复制视频坐标。
攻略版本、角色、键位或游戏状态不匹配时重新判断。

`input.perform` 执行短的声明式输入片段：目标标签/焦点、观察引用、按键/指针事件、
持续时长、最大截止时间与终止条件。宿主限制动作数和时长，禁止无界循环或模型代码。
静态 element_ref 点击走 browser.act，持续按键和动态轨迹走 input.perform，语义不能互相绕过。

停止、任务取消、焦点丢失、标签切换、页面替换或租约丢失时，释放所有由 Agent 持有的输入。
释放、取消和回收不受余额不足或工具额度耗尽阻止。输入可能已产生的外部效果不能靠释放撤销。

主模型制定目标与检查点；视觉模型判断阶段和局部动作；可信本地执行器维护时序。
不默认把高频画面传给远端大模型。对快速游戏，若推理与通信延迟无法满足操作窗口，
明确报告当前不支持，不能通过一次性执行长脚本掩盖控制能力不足。

## 10. 工具批处理与流程复用

可合并独立只读查询、多个字段提取、查询后的本地计算。
填表可使用带逐项 guard 的有限批次；每步重验必要条件，失败停止，返回哪些步骤已产生效果。
这不是数据库事务，不能承诺跨站原子性或自动回滚。

发送、支付、删除等检查点不夹带在便利的填表批次里。一次输入/按键也可能触发提交，
实际目标和上下文同样需要检查；不能因为操作叫 key 或 click 就把它标为低风险。

Core 可以在工作目录编写和测试可复用脚本，声明输入、前置条件、检查点和退出路径。每次执行重新定位临时元素引用，不能沿用旧截图坐标。脚本与模型调用使用同一浏览器 Broker；终端执行遵守目录、网络、进程、时长和输出限额。

## 11. 授权、交接与故障处理

任务授权说明：允许访问的系统和身份、允许读取/传递的数据、目的地、可执行动作、额度与期限。
只读调查默认不获得修改业务记录的权限。用户已授权的范围不重复请求确认。

高影响操作先准备再执行；批准绑定发件身份、接收方、具体内容/附件或业务对象及状态。
内容、目标、账户或文档发生相关变化时重新验证。用户可预先授权有界规则，宿主执行规则，
模型不能修改规则来给自己扩权。风险识别有盲点：无法确定作用的动作不能武断判为安全。

登录/二次验证/页面不支持/人机争用时进入 handoff_required，保留检查点；用户接管后
重新观察再继续。停止必须传播到模型请求、排队工具和在执行动作，任务结果区分已产生效果与未执行。

一次任务最多一个写入者持有某个标签页的动作租约；独立只读工作可受控并行。
重试分错误类型：只读可有界重试，过期引用重新观察，授权失败不自动扩大权限，副作用 unknown 先对账。

## 12. 预算、路由与成本计量

优化目标是“完成一个正确任务的总成本”，不是最低单次 token 或最低截图次数。
把观察、模型、工具、视频、等待、重试与用户接管都计入评测。

模型按能力路由，不写死厂商和价格：确定性操作优先本地；已验证的语义简单步骤可用轻量模型；
空间歧义交给视觉模型；跨系统冲突/复杂计划升级强推理。每次调用并非都转发完整历史或完整工具集。
多模型交接使用任务摘要、证据引用和未决项，保留关键事实，不能丢掉授权与不确定性。
先用单个有能力的模型建立正确性基线，再证明分工确实省钱，避免多代理交接成本超过收益。

任务预算至少有：

- 模型调用数、输入/输出 token、最大输出。
- 图像/视频帧、像素与字节；数据传输/保留量。
- 工具调用、动作数、重试次数和最大运行时间。
- 金额上限与当前已花费/已预留费用（配置了可用价格与计费口径时）。

调用前为并发工作预留费用，调用后按真实 usage 结算。中止后费用仍可能发生，不回滚花费。
没有可靠费率/usage 时不能宣称严格保证金额上限；使用保守可计算的调用/token 限额，
并明确该模式的限制。模型不能改写预算；达到上限暂停新付费/新业务动作，仍允许释放与核对已发起操作。

缓存复用必须同时考虑账户、授权、数据时效和文档状态。业务数据不是“曾经读过就永久可信”。
`wait` 通过浏览器事件与有界状态检查实现，不靠模型反复请求截图；事件丢失时允许受限复核。
动作用 delta/条件结果闭环，只有歧义或场景需要才扩大视觉信息；避免盲目重试后又调用强模型补救。

## 13. 当前 AgentCore ABI 19 的接口缺口

已核对本机完整 SDK：Run 输入支持文字/图片；HostToolV1 普通结果是文本，HostStreamToolV1
提供媒体代码与字节流，但这并不能证明一次工具调用的图片结果已被 provider 当作视觉内容接收。

实施前必须验证/补齐以下链路：

1. 宿主工具结果具有 typed text/image/table/artifact/error 内容与来源；不能把 base64 当普通文本。
2. Core 将图像引用解析为有权限的内容，通过各 provider adapter 的图像格式交给同一 Run 的下一轮。
3. 支持裁剪/尺寸/时间元数据、输出与像素限额、取消、保留期和结果释放所有权。
4. provider 不支持该图像/工具结果形态时清楚拒绝或选择已验证的降级，不偷偷新建 user Run。
5. fixture 验证实际 provider 请求包含图像且模型可以据此选动作；仅保存 PNG/返回路径不算通过。

工具目录按任务开放同样需要能力核对：ABI 19 有 Runtime 创建时的 HostTools 与 Session 的
allowed_tools。首版按 Session 选择能力集；若实现按 Run 动态调整工具声明，须明确 SDK
支持的更新方式，保留同一会话和授权历史，不为省 schema 开销而偷偷重建 Session。

若需要扩展二进制布局，应发布完整新 SDK 并更新 ABI revision、manifest 和各语言绑定。
不得只修改浏览器私有头文件以假装与 ABI 19 兼容。浏览器/renderer IPC 异步；SDK 同步回调
若需要等待，只可占用工作执行单元，不能阻塞 UI。当前单个 16 MiB worker 会串行化所有 Session，
在做并发任务时需要引入有界执行调度；不允许无界每任务创建一批线程。

## 14. 三个端到端验收

A. 联系方式 → 邮件：找到有来源的地址，标记歧义，形成草稿，使用正确发件身份，
按授权提交，验证发送状态。注入“点击后超时”验证不重复发送，并验证网页不能要求导出机密。

B. 财务 → ERP → CRM → BI：提供拆单、同名客户、缺失记录、分页、币种、异常与正常样本。
验证关联依据和分母；不能为了得出结论静默合并同名实体或忽略未匹配数据。

C. 攻略 → 游戏：本地测试视频与游戏具有可验证状态。理解攻略前提，执行有界动作，
遇到状态差异重新观察，取消/切换标签时无残留按键。首版选节奏较慢场景，不承诺所有网页游戏。

各场景同时测正确率、证据完整性、权限违规、重复副作用、用户接管、模型费用、
调用/图像/字节、端到端延迟和恢复成本。与“每步全屏 + 强模型”基线对照，先设错误/安全门槛，
通过后比较成本；当前没有测得的节省百分比或费用报价。

## 15. 全系统接口与验证

完整系统见 [ARCHITECTURE.md](ARCHITECTURE.md)。所有浏览器动作，无论来自模型、站点脚本还是本地 coding，都经过同一 Broker；文件与进程在独立的宿主权限边界执行。工具返回统一的状态、证据、产物引用、预算消耗和可恢复检查点。

在共同契约下分别补齐 Broker、MCP Client、Coding Host、Task Store、多模态适配、UI 和调度，验收覆盖前三个完整场景。还需验证：旧地图不触发盲目操作；脚本权限不能绕过 Broker；本地数据处理保持来源；MCP 断连和能力变化可恢复；取消同时终止输入与子进程。

当前原型仍只向 Session 提供原生会话能力，尚未接入这些页面、MCP 和 coding 工具。实现前核对 SDK 的实际工具名、schema、能力协商和不支持项；工具名已定义不等于已可执行。

工具目录保持稳定，在宿主调度中加入局部委托与候选决策接口，详见 [JEV_RESEARCH.md](JEV_RESEARCH.md)。这是内部执行契约，不为每个动作多添一个强制模型工具调用。高层 Core 保留完整 coding/MCP 能力，局部选择仅使用已经验证参数和状态的候选。图片与 Box 实验能力需单独协商和验证。
